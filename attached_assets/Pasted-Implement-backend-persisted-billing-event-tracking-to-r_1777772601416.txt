Implement **backend-persisted billing event tracking** to replace localStorage-only history, while maintaining backward compatibility.

---

# 🎯 OBJECTIVE

Move billing event tracking from **client-only (localStorage)** to **server-persisted**, so:

* events persist across devices
* subscription history is reliable
* audit trail is production-grade

---

# 🗄️ DATABASE SCHEMA

Create new table:

```
billing_events
```

Fields:

* id (uuid, pk)
* userId (fk → users.id, indexed)
* type (string enum)
* label (string, nullable)
* metadata (jsonb, optional)
* createdAt (timestamp, default now)

---

# 🔌 API ENDPOINTS

## 1. Create event

POST `/api/billing/events`

Body:

```
{
  type: "upgrade_prompt_clicked" | "subscription_started" | "billing_skipped",
  label: "from_dashboard_banner",
  metadata?: {}
}
```

Rules:

* must be authenticated
* userId derived from token
* non-blocking write (fail silently if needed)

---

## 2. Get events

GET `/api/billing/events`

Returns:

* latest 50 events
* sorted DESC by createdAt

---

# 🧠 BACKEND BEHAVIOUR

* Do NOT block main flows if logging fails
* Wrap writes in try/catch (fire-and-forget)
* Validate event types (whitelist only)
* Index userId for fast lookup
